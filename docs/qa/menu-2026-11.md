# ui-dropdown / ui-menu QA (November 2026)

Screenshots: `docs/qa/menu/`, three skins by light and dark by 360, 768
and 1280 px (`apps/playground/scripts/qa-menu-shots.mjs`). Checked by
`apps/playground/e2e/menu.spec.ts` in all six skin and mode combinations,
plus the shared axe, keyboard and reduced-motion specs.

## Not done by CSS (documented for the consumer)

Roving focus, typeahead, Enter and Space activation, Escape and returning
focus, closing on Tab and on a click outside, `aria-haspopup` and
`aria-expanded`, and collision handling. The keyboard contract is in
`vocabulary.md`. Uniskin stays CSS-only: no helper was added, so the 1.0
promise holds for the core package; the playground demo has a short
working handler, and Radix `DropdownMenu` and Ark `Menu` are the
recommended headless options (they set `data-highlighted`, which the CSS
honours).

## Findings

- **Focus in the same tick.** A plain `visibility` transition keeps the
  panel hidden for its first frame, so a script that opened the menu and
  focused the first item at once focused nothing. The open state now shows
  at once; only closing is delayed (fade, then hide). A unit test pins both
  transitions and `writing-adapters.md` records the rule.
- **`aria-selected` is not valid on a menu item** (axe `aria-allowed-attr`).
  The current item is the `ui-active` class; for links use
  `aria-current="page"`, for checkbox and radio items `aria-checked`.
- **`aria-controls` on a hidden menu** is reported by axe as unverifiable
  while the menu is closed. It is optional for menu buttons, so the demo
  omits it.
- **Test sampling.** The hover tint fades over 0.15s; the focus test waits
  for it instead of sampling mid-transition.
