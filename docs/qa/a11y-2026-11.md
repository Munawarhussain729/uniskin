# Accessibility audit — 2026-11-08

Scope: the playground (`apps/playground/index.html`) rendered with each of the
three skins (`default`, `shadcn`, `daisyui`) × `{light, dark}` mode.

Method:

- `axe-core` via `@axe-core/playwright` on the built page
  (`apps/playground/e2e/axe.spec.ts`) — asserts **no serious or critical
  violations** after the documented allowlist below. axe results per run are
  dumped to `apps/playground/tests/__out__/axe-<adapter>-<mode>.json`.
- Keyboard/state checks (`e2e/keyboard.spec.ts`) — full Tab traversal,
  measured `:focus-visible` ring contrast (≥3:1, per WCAG 2.4.13
  interpretation: ring colour vs the backdrop it is drawn on), disabled-state
  announcement, busy-label readability, tabs/modal ARIA.
- `prefers-reduced-motion` check (`e2e/motion.spec.ts`).

Per task scope this is **report-only** — no `packages/*/src` or colour tokens
were changed. Playground-markup fixes that were made are listed at the end.

## Allowlist

Defined in `e2e/axe.spec.ts`; each entry is `kind: "upstream"` (intentional —
mirrors the upstream design system, per the task brief) or `kind: "defect"`
(a real bug tracked below). Axe `incomplete` (needs-review) items are gated by
the same mechanism after manual review.

## 2. Real defects found

### D1 — default skin: light-mode intent text/fill below AA

Rule `color-contrast`, skin `default`, mode `light`:

| Selector | Ratio | Colours |
|---|---|---|
| `.ui-button.ui-success`, `.ui-badge.ui-success` (solid) | 3.13:1 | `#f8f8f8` on `#00a16b` |
| `.ui-button.ui-danger`, `.ui-badge.ui-danger`, `.ui-alert.ui-danger` (solid) | 4.48:1 | `#f8f8f8` on `#db2c2b` (0.02 under AA) |
| `.ui-button.ui-success.ui-outline`, `.ui-button.ui-success.ui-ghost`, `.ui-badge.ui-success.ui-outline`, `.ui-tabs.ui-ghost.ui-success .ui-tab` | 3.18:1 | `#00a16b` on `#fafafa` |
| `.ui-button.ui-warning.ui-outline`, `.ui-button.ui-warning.ui-ghost` | 1.94:1 | `#e3ae28` on `#fafafa` |

Same defect surfaces under `shadcn` light (success slots fall back to default
tokens): `.ui-button.ui-success`, `.ui-badge.ui-success` — 3.13:1.

Proposed fix (token task, not this one): darken `--ui-success` (~`#00754c`
family) and `--ui-danger` (~`#c81e1e`) for light mode, and/or give
outline/ghost text a darker `--ui-warning`-derived text colour
(`--ui-c-text`), keeping the bright fill only where a dark `-on-c` label sits
on it.

### D2 — focus rings below 3:1

Measured post-transition (transitions are disabled in the harness so the
settled ring is what users actually see):

| Selector | Skin | Mode | Ratio | Detail |
|---|---|---|---|---|
| `.ui-input`, `.ui-textarea`, `.ui-select` (all variants) | default | light | 1.18–1.47:1 | Ring is `box-shadow: 0 0 0 3px color-mix(--ui-c 25%, transparent)` — a 25%-alpha tint. |
| same | default | dark | 1.44–1.78:1 | Same root cause. |
| `.ui-button.ui-outline.ui-active`, `.ui-button.ui-outline[aria-pressed]` | shadcn | light / dark | 1.60:1 / 1.05:1 | The pressed-state inset shadow *replaces* the focus ring (`rgba(0,0,0,0.2)` best layer). |
| `.ui-button.ui-success/.ui-warning/.ui-danger` (solid+outline+ghost+soft), `.ui-input.ui-danger`, `.ui-input.ui-success`, `.ui-textarea.ui-warning.ui-soft` | daisyui | light | 1.69–2.74:1 | Intent-coloured outline ring — mirrors upstream daisyUI. |
| `.ui-button` neutral `.ui-outline`/`.ui-ghost`/`.ui-soft`/`.ui-active`/`[aria-pressed]`, card-footer ghost button | daisyui | dark | 1.12–1.26:1 | Ring = `oklch(0.14)` on `#18181b` — invisible. |

Proposed fix: default skin should make the field ring match the button ring
(`outline: 2px solid var(--ui-ring)` or a ≥45%-alpha shadow); shadcn should
keep a separate ring layer on pressed outline buttons; daisyui should use a
higher-contrast ring colour (e.g. `base-content`) for low-contrast intents in
light and for neutral buttons in dark.

### D3 — `prefers-reduced-motion` ignored by the loading spinner

- Rule (custom check): for `button.ui-loading` and `button[aria-busy="true"]`,
  the `::after` spinner (`animation: ui-spin 0.6s linear infinite`) **keeps
  running** under `prefers-reduced-motion: reduce` — in **all three skins**
  (the fallback loading state is shared). The only reduced-motion rule
  emitted anywhere is `.ui-modal { transition: none }` — verified working
  (positive control).
- Fix: under `@media (prefers-reduced-motion: reduce)`, set
  `animation: none` on the `::after` spinner (and any `ui-pulse` element
  animation) — keep a static "busy" affordance instead.

### D4 — busy label readability (daisyui)

`button.ui-loading` / `button[aria-busy]` are `ui-secondary` in the demo;
labels measure **3.04:1** (`#f9e4f0`-ish on `oklch(0.65 0.241)` pink) — below
4.5:1. Same root cause as the daisyUI secondary palette in §1; a spinner-only
state or higher-contrast `secondary-content` would fix it.

## 3. Reviewed axe `incomplete` items

- `color-contrast` on `select.ui-select` ×3 (all skins/modes): axe can't
  resolve the background because the chevron is an inline-SVG background
  image. Measured manually: text ≈ `#1b1f29` on white (light) → ~15–18:1;
  ≈ `#f8fafc` on dark surface (dark) → ~15:1. OK.
- `aria-valid-attr-value` on `#open-modal` (critical, all runs): axe wanted
  review of `aria-controls` pointing at a hidden `<dialog>`. Resolved by
  removing `aria-controls` (`aria-haspopup="dialog"` remains).

## 4. Keyboard & state findings

- Tab order reaches **all 81** interactive elements in every skin × mode;
  nothing focusable is skipped (disabled/inert elements correctly excluded).
- `ui-disabled`/`aria-disabled`/`:disabled`: after the markup fixes below,
  every disabled-looking control is either unfocusable or announced
  (`aria-disabled="true"`). No violations.
- `aria-busy`/`ui-loading` labels: readable in default & shadcn; daisyui
  failure = D4.
- Tabs: every `.ui-tab` now carries `role="tab"` + `aria-selected` (incl.
  `"false"`); every `.ui-tabs` has `role="tablist"` and one selected tab.
  Note: arrow-key nav/roving tabindex + `role="tabpanel"` are still unstyled
  JS concerns — the demo intentionally implements styling only (see
  `docs/vocabulary.md` → `ui-tabs`).
- Modal: now a real `<dialog class="ui-modal">` opened via `showModal()` —
  Esc-to-close, focus containment and focus-restore verified.

## 5. Playground markup fixes applied (this task)

- Light/dark toggle (`#theme-switcher`) setting `class="dark|light"` +
  `data-theme` on `<html>`; persisted in `localStorage`, defaults to the OS
  setting, follows OS changes while no explicit choice is stored, and a
  `?theme=` param overrides for QA links.
- Adapter + theme pills restyled with explicit page-level colours for both
  modes (they're page chrome, not Uniskin components) plus a `:focus-visible`
  outline.
- `.ui-disabled` demo button → `aria-disabled="true"` (announced, still
  focusable — the intended pattern); `.ui-loading` demo button →
  `aria-busy="true"`; disabled tab → `disabled` + `aria-disabled` +
  `aria-selected="false"`; every non-selected tab → `aria-selected="false"`.
- `<div class="ui-modal">` demo → native `<dialog>` + `form method="dialog"`
  buttons + backdrop-click close.
- Page content wrapped in `<main>` (landmark); `aria-controls` dropped from
  the modal trigger.
